# Мануал для ИИ-тренера: работа с приложением «Тренировки»

Версия формата файла: `personal-training-diary-coach-plan` / `1`

## 1. Как устроен дневник

«Тренировки» — локальное PWA-приложение для одного пользователя. Оно открывается в браузере или как установленное приложение на телефоне. Семь разделов:

- **Главная** — план на сегодня, текущая неделя, последняя тренировка и сводка.
- **Тренировка** — запись упражнений, веса, повторов и подходов; таймер тренировки и отдыха.
- **История** — календарь и завершённые занятия, их можно просматривать и редактировать.
- **Упражнения** — библиотека упражнений, блоки и программы тренировок.
- **Прогресс** — рабочие веса, объём, рекорды, регулярность и графики.
- **Тело** — вес тела и замеры в сантиметрах.
- **Профиль** — цели, достижения, настройки и резервные копии.

Записи хранятся локально в браузере пользователя. У приложения нет аккаунта, сервера, синхронизации или автоматической передачи данных тренеру. Нейросеть взаимодействует с дневником только через файлы, которые пользователь сам экспортирует и передаёт ей.

## 2. Роли в связке «пользователь — приложение — ИИ-тренер»

**Приложение — журнал фактов.** Оно хранит то, что действительно было выполнено: даты тренировок, упражнения, подходы, вес, повторы, замеры, рабочие веса и рекорды.

**ИИ-тренер — аналитик и автор плана.** Он читает переданный пользователем экспорт, анализирует фактическую динамику, готовит следующую версию программы и возвращает отдельный JSON-файл для импорта.

**Пользователь — связующее звено и источник подтверждения.** Он сам записывает фактические подходы в зале, выбирает когда поделиться экспортом с тренером и вручную загружает новый файл программы. Нейросеть не может самостоятельно прочитать данные с телефона или изменить дневник напрямую.

## 3. Обычный цикл взаимодействия

1. Пользователь ведёт тренировку в приложении и после подходов записывает фактические килограммы и повторы. После завершения занятие попадает в историю.
2. Когда нужен анализ (например, раз в неделю или после завершения тренировочного блока), пользователь открывает **Профиль → Данные и резервные копии → Скачать JSON-копию**.
3. Пользователь отправляет экспорт ИИ-тренеру в чате и просит оценить динамику. Экспорт содержит тренировочную историю, упражнения, программы, замеры, цели и настройки. Передавая файл внешнему ИИ-сервису, пользователь сознательно делится его содержимым; в нём могут быть личные данные о теле и тренировках.
4. ИИ-тренер изучает фактические результаты, задаёт уточняющие вопросы только о том, чего не хватает для безопасного решения, и формирует новую программу в файле `coach-plan.json` по схеме ниже.
5. Пользователь получает файл от тренера, открывает приложение и выбирает **Профиль → Программа от ИИ-тренера → Загрузить программу тренера**.
6. Приложение проверяет структуру и показывает предпросмотр. После подтверждения новые упражнения, блоки и программы добавляются в библиотеку. Готовые дни появляются в разделе **Упражнения → Программы**, а назначенные дни недели — в планах на главной.
7. Пользователь выбирает день программы, начинает тренировку и записывает фактические подходы. При старте вес и повторы автоматически берутся из предыдущего выполнения этого упражнения. Вес из файла тренера используется только как резервное начальное значение, если истории ещё нет.
8. В следующий раз пользователь экспортирует свежий JSON, и цикл повторяется.

## 4. Важное правило безопасности данных

Файл тренера **только дополняет** дневник. У отдельной кнопки импорта программы нет режима замены.

- Существующие тренировки, подходы, замеры, достижения, цели и настройки не удаляются.
- Существующие упражнения сопоставляются по названию и оборудованию; повторные копии в библиотеке не создаются.
- У программы и блока есть устойчивый ID. Повторная загрузка того же файла пропускает уже добавленную программу/блок.
- Импорт не записывает завершённые тренировки задним числом и не придумывает результаты. Он создаёт только шаблоны/план.
- Если тренер выпускает обновлённую версию программы, он должен дать ей новый `id` (например, `upper-lower-v2`). Старая программа останется в дневнике, новая добавится рядом. Это намеренно: старые назначения и история не должны неожиданно меняться.
- Не включайте в программу значения замеров тела и не создавайте фиктивные PR. Цели по рабочим весам можно передать в `liftGoals`, но их значения должны быть обоснованы данными пользователя.

Обычный импорт резервной копии JSON/XLSX — отдельная функция. Он остаётся режимом переноса/восстановления данных и не нужен для загрузки плана тренера.

## 5. Формат файла тренера

Кодировка: UTF-8. Расширение: `.json`. Корневые поля:

| Поле | Тип | Обязательно | Назначение |
|---|---|---:|---|
| `format` | строка | Да | Строго `personal-training-diary-coach-plan` |
| `version` | число | Да | Строго `1` |
| `generatedAt` | ISO-дата/время | Рекомендуется | Когда файл сформирован |
| `coachNote` | строка | Нет | Краткое объяснение логики программы |
| `exercises` | массив | Да | Единый каталог упражнений, на который ссылаются дни и блоки |
| `blocks` | массив | Нет | Повторно используемые комплексы упражнений |
| `programs` | массив | Да | Программы и их тренировочные дни |
| `liftGoals` | массив | Нет | Цели по рабочим весам |

### 5.1. Упражнения — `exercises`

У каждого упражнения:

- `id` — стабильный короткий ASCII-идентификатор, например `barbell-bench-press`. Не меняйте его между файлами, пока речь об одном и том же упражнении.
- `name` — понятное название на русском.
- `muscles` — массив групп мышц; используйте названия из списка ниже или близкие общепринятые названия.
- `equipment` — одно значение: `Штанга`, `Гантели`, `Блок`, `Тренажёр`, `Собственный вес` или `Другое`.
- `stepKg` — шаг изменения веса в кг, обычно `1`, `1.25`, `2.5` или `5`.
- `restSeconds` — стандартный отдых в секундах.
- `note` — техника/ограничения, необязательная строка.
- `description` — дополнительное краткое пояснение, необязательно.

Пример:

```json
{
  "id": "barbell-bench-press",
  "name": "Жим штанги лёжа",
  "muscles": ["Грудь", "Трицепс", "Плечи"],
  "equipment": "Штанга",
  "stepKg": 2.5,
  "restSeconds": 150,
  "note": "Контролировать опускание, сохранять устойчивое положение лопаток"
}
```

### 5.2. Программа — `programs`

Каждая программа содержит:

- `id` — уникальный стабильный ID версии. Для новой версии создавайте новый ID.
- `name` — название программы.
- `description` — краткая логика/цель цикла.
- `days` — массив тренировочных дней.

У каждого дня:

- `id` — стабильный ID внутри программы, ASCII.
- `name` — например `День А — Верх тела`.
- `weekday` — день недели: `0` воскресенье, `1` понедельник, `2` вторник, `3` среда, `4` четверг, `5` пятница, `6` суббота. `null` — день не назначен. Учитывайте, что у пользователя может быть своя неделя/график.
- `exercises` — список элементов плана в нужном порядке.

Элемент `day.exercises`:

| Поле | Тип | Обязательно | Пример |
|---|---|---:|---|
| `exerciseId` | строка | Да | `barbell-bench-press` — ссылка на `exercises[].id` |
| `sets` | целое 1–20 | Да | `3` |
| `repsMin` | целое 1–100 | Да | `6` |
| `repsMax` | целое от `repsMin` до 100 | Да | `8` |
| `startingWeightKg` | число или `null` | Нет | `40` или `null` |
| `warmupSets` | целое 0–5 | Нет | `2` |
| `note` | строка | Нет | Подсказка тренера для упражнения |

Диапазон повторов задаёт рабочий ориентир. `startingWeightKg` — только стартовая подсказка, а не команда обязательно поднимать этот вес. История приложения имеет приоритет: если пользователь уже делал упражнение, дневник сам подставит последние результаты. Не угадывайте стартовый вес, когда данных нет: оставляйте `null`.

`warmupSets` — число разминочных подходов, которые приложение добавит при запуске дня, если пользователь включил разминку в настройках. Разминочные подходы не входят в рабочий объём и рекорды.

### 5.3. Блоки — `blocks`

У блока есть `id`, `name`, необязательный `note` и `items`. Каждый элемент `items` использует те же поля, что элемент `day.exercises`: `exerciseId`, `sets`, `repsMin`, `repsMax`, опционально `startingWeightKg`, `warmupSets`, `note`.

### 5.4. Цели — `liftGoals`

Необязательный массив целей. У цели: `id`, `exerciseId`, `targetWeightKg`, `targetReps`, необязательный `deadline` (`ГГГГ-ММ-ДД`) и `note`. `exerciseId` должен ссылаться на упражнение из каталога. Не создавайте цель без достаточных данных и согласованного с пользователем ориентира.

## 6. Минимальный пример структуры

Полный пример, который можно использовать как исходную заготовку, лежит рядом с этим документом в файле `coach-plan-template.json`. В нём есть несколько упражнений, блоков и двухдневная программа. Значения веса оставлены `null`, потому что это обезличенный шаблон, а не рекомендация конкретному человеку.

## 7. Как ИИ-тренеру анализировать экспорт дневника

Экспорт из приложения — JSON с верхним объектом `application`, `formatVersion`, `createdAt` и `state`. Основные поля находятся внутри `state`:

- `workouts[]` — завершённые занятия. В каждом `workout.exercises[]` находятся упражнения, внутри них `sets[]` — фактические подходы.
- `exercises[]` — библиотека с мышечными группами, оборудованием, шагом веса и временем отдыха.
- `programs[]` — действующие шаблоны и расписания.
- `measurements[]` — замеры с датами и единицами `кг`/`см`.
- `goals` — цели пользователя.
- `records[]` — журнал личных рекордов.
- `settings` — предпочтения интерфейса и расчётов.

При анализе:

1. Используйте только `workouts` с заполненным `endAt` как завершённые занятия.
2. Для рабочего объёма не включайте подходы с `type: "warmup"`; рабочий подход — `type: "work"` (или отсутствующий тип в старых записях).
3. Считайте фактические повторы/вес из `sets`. Не подменяйте их плановыми значениями.
4. Сравнивайте одинаковые упражнения и сопоставимые диапазоны дат. Учитывайте смену варианта упражнения/оборудования.
5. Измерения тела сравнивайте только по одинаковому `type` и одинаковым единицам. Не делайте вывод о здоровье по дневнику.
6. Не объявляйте прогрессом изменение, которое объясняется неполной неделей, меньшим количеством тренировок или другой техникой/амплитудой.
7. При нехватке данных прямо пишите об этом, не выдумывайте повторения, веса, диагнозы и ограничения.
8. Давайте рекомендации с учётом восстановления, переносимости нагрузок и обратной связи пользователя. При боли, травме или медицинских ограничениях не ставьте диагноз; предложите прекратить болезненное упражнение и обратиться к профильному специалисту.
9. Не меняйте ID упражнений, которые уже есть в каталоге, если это то же движение. Старайтесь повторно использовать существующие `exercises[].id`.
10. Возвращайте новую программу в отдельном JSON-файле, а не полную копию экспорта пользователя.

## 8. Системный промпт для нейросети-тренера

Можно вставить этот текст в инструкции отдельного ИИ-тренера:

> Ты — мой тренер по силовым тренировкам и аналитик моего тренировочного дневника. Я веду фактические занятия в приложении «Тренировки» и периодически передаю тебе JSON-экспорт. Сначала анализируй завершённые занятия, динамику упражнений, объём, частоту, замеры и мои текущие цели. Не выдумывай фактические результаты и не считай план выполненной тренировкой. Если данных недостаточно, сообщай об ограничениях и уточняй только действительно важное.
>
> Когда нужен новый план или изменение программы, сформируй отдельный UTF-8 JSON-файл по формату `personal-training-diary-coach-plan`, версия `1`, согласно `COACH_AI_MANUAL.md`. Включи весь необходимый каталог упражнений, программы с днями недели, рабочие подходы/диапазоны повторов, отдых, шаг веса, необязательные разминки и блоки. Для уже известных упражнений сохраняй прежние ID и названия. Вес старта указывай только при достаточном основании; иначе ставь `null`. Никогда не включай фальшивые завершённые тренировки и замеры.
>
> Файл должен быть добавочным: сохраняй стабильные ID программы и блоков; для новой редакции программы создавай новый ID версии, чтобы приложение добавило её рядом со старой. Не включай команды на очистку/замену дневника и не генерируй полную резервную копию вместо плана. После файла кратко объясни, что изменилось и как загрузить его через Профиль → Программа от ИИ-тренера.

## 9. Как давать обратную связь после зала

После каждой тренировки пользователь может написать тренеру кратко: «Выполнил День А. Жим: 40×8, 40×8, 42,5×7. Последний подход RPE 9. Восстановление нормальное». Но лучше периодически прикладывать свежий JSON-экспорт: тогда тренер увидит всю структуру и не будет вручную собирать неполную историю из сообщений.

Пользователь может дополнительно сообщить субъективные ощущения: сон, усталость, болезненность, стресс, желание/нежелание тренироваться, особенности зала и доступное оборудование. Эти наблюдения не хранятся автоматически в дневнике, если пользователь сам не записал их в заметки.

## 10. Чего тренер не может делать напрямую

- Самостоятельно читать IndexedDB или историю приложения.
- Видеть, был ли реально выполнен подход, пока пользователь не записал результат и не поделился экспортом/сообщением.
- Удалять или редактировать локальные записи.
- Загружать файл в приложение от имени пользователя.
- Получать данные о тренировках через GitHub Pages.

Тренер готовит файл; пользователь импортирует его. Именно это разделение сохраняет контроль пользователя над локальными данными.
